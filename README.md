# UI-автотесты для веб-приложения «Пиццерия "Итальянский уголок"»

Раз ты открыл это, то здесь тебя ждет набор автоматизированных UI-тестов для учебного стенда: (https://slqamsk.github.io/cases/pizza/v08/)

## Технологический стек
* **Язык:** Java 17
* **Фреймворк автоматизации:** Selenide 7.5.1
* **Тестовый движок:** JUnit 5
* **Сборщик:** Maven
* **Отчетность:** Allure Report
* **Паттерн проектирования:** Page Object Model (`pages` + `tests`)

## Покрытие тестами (8 сценариев)
1. **Начальное состояние:** проверка нулевого счетчика корзины, пустой корзины и отсутствия заказов при первом входе.
2. **Недоступный товар:** проверка блокировки карточки и кнопки заказа для пиццы «Трюфельная» (`unavailable` / `disabled`).
3. **«Пицца дня» и скидка 10%:** динамическое определение пиццы дня, математическая проверка скидки 10% на карточке и сверка итоговой стоимости в корзине.
4. **Работа с корзиной:** добавление нескольких пицц, подсчет итоговой суммы и полная очистка корзины.
5. **Негативный сценарий (пустая корзина):** проверка системного предупреждения `Корзина пуста!` при попытке оформить пустой заказ.
6. **Негативный сценарий (валидация полей):** проверка предупреждения `Пожалуйста, заполните все поля!` при подтверждении заказа с незаполненными данными клиента.
7. **Сквозной E2E-сценарий:** добавление товара, заполнение формы клиента, подтверждение заказа, проверка чека и сохранение заказа в разделе «Мои заказы».
8. **Отмена заказа:** проверка отказа от отмены (`Отмена` — заказ сохраняется) и подтверждения отмены (`OK` — заказ отменяется).

## Выявленный дефект стенда
В ходе исследовательского и автоматизированного тестирования обнаружен дефект в сценарии **№3**: на главной странице скидка 10% на случайную «Пиццу дня» рассчитывается корректно, однако при переходе в корзину товар добавляется по полной стоимости без учета скидки (тест падает на проверке итоговой суммы в корзине, что фиксируется в отчете Allure).

## Запуск тестов и генерация отчета
```bash
mvn clean test
mvn allure:serve
```
